Migrating from CraftMyPDF to IronPDF: the .NET migration reference

technical depth for .NET teams evaluating a PDF library switch

Framing

Template-driven PDF generation APIs occupy a specific architectural position in the cloud services landscape. Rather than accepting raw HTML or a full rendering configuration, they offer a visual template builder — typically a drag-and-drop editor in a web UI — where the PDF layout is designed once, stored in the cloud, and then populated with data via API calls. The appeal is that document layout work is separated from application code: designers can update templates without touching the .NET codebase.

CraftMyPDF is one such template-based cloud PDF generation service. It provides a no-code template editor alongside an HTTP API that accepts a template ID and a data payload, renders the PDF on remote infrastructure, and returns a download link or binary. .NET integrations are built using HttpClient or an SDK wrapper that abstracts the HTTP layer. Teams adopt this model when reducing PDF development complexity is valued over operational control, typically in the early stages of a product when template volume is small and design iterations are frequent.

Re-evaluating this model typically happens when PDF volume makes per-call cloud pricing material, when data residency requirements prevent content from leaving the application process, when rendering fidelity for complex layouts is a recurring friction point, or when the organization wants to bring PDF logic under version control alongside the rest of the application. This guide is for .NET engineers evaluating or executing a migration from CraftMyPDF to IronPDF.

What CraftMyPDF Is Designed to Do

CraftMyPDF is a cloud-based PDF generation service. The product status and last release should be verified in official documentation. The service provides a web-based WYSIWYG template designer where PDF layouts are created visually, stored on CraftMyPDF's infrastructure under a template ID, and then populated with data via a REST API. The rendering engine is Chromium-based.

The .NET integration model uses an HTTP client to POST a JSON payload containing the template ID and a data object; the API returns a temporary download URL or inline PDF bytes depending on the endpoint configuration. The install footprint on the client side is minimal — only an HTTP client and JSON serialization are required; no native binaries or NuGet dependencies specific to CraftMyPDF are needed beyond any SDK wrapper the team has adopted. The product status, .NET SDK availability, and exact API shape should be verified in official documentation, as cloud API services update their feature set and pricing independently of any client library versioning.

Architectural Differences

The architectural shift from CraftMyPDF to IronPDF is a transition from a remote cloud service to an in-process .NET library. Every CraftMyPDF render call involves an HTTP round trip, external template storage, and rendering on CraftMyPDF's infrastructure. IronPDF renders HTML templates in-process using an embedded Chromium engine on the application host.

This shift has several downstream consequences. Template storage moves from CraftMyPDF's cloud editor to HTML files or string templates in the application codebase (or a CMS, database, or file system). Template rendering logic that was expressed as a JSON data binding in CraftMyPDF's template format is replaced by C# string interpolation, a templating engine (Razor, Scriban, Handlebars.NET, Fluid, or similar), or HTML generation code. Data residency improves because documents are generated entirely within the application process. Outbound HTTP dependencies are removed from the PDF generation path, eliminating a category of network failure and latency.

IronPDF's main rendering type is ChromePdfRenderer. It is stateless and configured via ChromePdfRenderOptions. The resulting PdfDocument implements IDisposable and must be used in a using block. The async rendering guide covers the Task<PdfDocument>-returning async methods suitable for ASP.NET Core request handlers. License setup is a one-time startup call via IronPdf.License.LicenseKey — see the license setup guide.

Operation Comparisons

Template-Based PDF Generation

CraftMyPDF — Template Rendering (via HTTP)

using System.Net.Http;
using System.Net.Http.Json;
using System.Text.Json;

// CraftMyPDF generates a PDF by merging a data object into a stored cloud template
var client = new HttpClient();
client.DefaultRequestHeaders.Add("X-API-KEY", "YOUR-CRAFTMYPDF-API-KEY");

// Data payload is bound to merge fields defined in the CraftMyPDF template editor
var requestBody = new
{
    template_id = "abc123xyz",   // Template ID from CraftMyPDF dashboard
    data = new
    {
        recipient_name = "Jane Smith",
        invoice_number = "INV-1042",
        line_items = new[]
        {
            new { description = "Widget A", qty = 10, unit_price = 5.00, total = 50.00 }
        },
        grand_total = 50.00,
        due_date = "2026-03-31"
    }
};

var response = await client.PostAsJsonAsync(
    "https://api.craftmypdf.com/v1/create", requestBody);

response.EnsureSuccessStatusCode();

// Parse the JSON envelope for the PDF URL or inline bytes
var result = await response.Content.ReadFromJsonAsync<JsonElement>();
string pdfUrl = result.GetProperty("file").GetString()!;

// Download the PDF from the temporary URL
using var pdfResponse = await client.GetAsync(pdfUrl);
byte[] pdfBytes = await pdfResponse.Content.ReadAsByteArrayAsync();

await File.WriteAllBytesAsync("invoice.pdf", pdfBytes);

Concrete constraints:

  • Every render is a two-step network operation: API call + PDF download from the returned URL.
  • The template is stored on CraftMyPDF's infrastructure; template updates require the web UI, not the codebase.
  • The data binding schema is defined by the template field names created in the CraftMyPDF editor — a mismatch between field names and the data object silently produces empty fields.
  • Temporary PDF URLs have expiry times; the download must happen promptly.
  • API rate limits apply; high-volume rendering requires retry/backoff logic.
  • Document content leaves the application process — a data residency concern for regulated content.

IronPDF — Template Rendering (in-process)

using IronPdf;

// Templates are HTML strings in the codebase — no external template storage
// A .NET templating engine is used for data binding (Razor, Scriban, Fluid, etc.)
// This example uses simple string interpolation for illustration

var renderer = new ChromePdfRenderer();
renderer.RenderingOptions.PaperSize = IronPdf.Rendering.PdfPaperSize.A4;
renderer.RenderingOptions.MarginTop = 15;
renderer.RenderingOptions.MarginBottom = 15;
renderer.RenderingOptions.MarginLeft = 15;
renderer.RenderingOptions.MarginRight = 15;

// Build the HTML template with data bound in C#
string recipientName = "Jane Smith";
string invoiceNumber = "INV-1042";
string dueDate = "2026-03-31";
double grandTotal = 50.00;

string html = $@"
<!DOCTYPE html>
<html>
<head>
<style>
  body {{ font-family: Arial, sans-serif; font-size: 11pt; }}
  .header {{ display: flex; justify-content: space-between; margin-bottom: 20px; }}
  h2 {{ margin: 0; }}
  table {{ width: 100%; border-collapse: collapse; margin-top: 20px; }}
  th, td {{ border: 1px solid #ddd; padding: 8px; }}
  th {{ background: #f5f5f5; }}
  .total {{ text-align: right; font-weight: bold; margin-top: 10px; }}
</style>
</head>
<body>
  <div class='header'>
    <h2>Invoice {invoiceNumber}</h2>
    <div>Due: {dueDate}</div>
  </div>
  <p>Bill To: <strong>{recipientName}</strong></p>
  <table>
    <tr><th>Description</th><th>Qty</th><th>Unit Price</th><th>Total</th></tr>
    <tr><td>Widget A</td><td>10</td><td>$5.00</td><td>$50.00</td></tr>
  </table>
  <div class='total'>Grand Total: ${grandTotal:F2}</div>
</body>
</html>";

// Single in-process call — no HTTP, no temp URL, no API key per call
using var pdf = renderer.RenderHtmlAsPdf(html);
pdf.SaveAs("invoice.pdf");

The IronPDF approach moves the template into the codebase as an HTML file or string, and data binding becomes standard C# — string interpolation, Razor, or a dedicated templating library. The HTML string to PDF guide and rendering options reference cover the full configuration surface.

Async Rendering in ASP.NET Core

CraftMyPDF — Async in ASP.NET Core

using System.Net.Http;
using System.Net.Http.Json;
using Microsoft.AspNetCore.Mvc;

[ApiController] [Route("invoices")] public class InvoiceController : ControllerBase { private readonly HttpClient _httpClient;

public InvoiceController(IHttpClientFactory factory) { _httpClient = factory.CreateClient("craftmypdf"); _httpClient.DefaultRequestHeaders.Add("X-API-KEY", "YOUR-CRAFTMYPDF-API-KEY"); }

[HttpGet("{id}")] public async Task GetInvoice(int id) { // Fetch invoice data from database var invoiceData = await GetInvoiceData(id);

// POST to CraftMyPDF — network call on every request var response = await _httpClient.PostAsJsonAsync( "https://api.craftmypdf.com/v1/create", new { template_id = "abc123xyz", data = invoiceData });

response.EnsureSuccessStatusCode();

var result = await response.Content.ReadFromJsonAsync(); string pdfUrl = result.GetProperty("file").GetString()!;

using var pdfStream = await _httpClient.GetStreamAsync(pdfUrl); return File(pdfStream, "application/pdf", $"invoice-{id}.pdf"); }
