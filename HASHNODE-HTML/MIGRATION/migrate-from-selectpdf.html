Migrating from SelectPdf to IronPDF: the engineering breakdown

effort estimation, API mapping, and production considerations

Framing

SelectPdf was a commercial .NET HTML-to-PDF library with both a free Community Edition (limited to 5 pages) and paid commercial tiers. It offered a comprehensive API for converting HTML strings, files, and URLs to PDF, with extensive configuration for page layout, headers, footers, security, digital signatures, and accessibility. For teams that found it during its active commercial years, SelectPdf's broad feature set and its relatively conventional .NET API made it an accessible alternative to larger commercial PDF suites.

SelectPdf is now effectively discontinued — its commercial offering is no longer receiving active development, and its free Community Edition remains frozen. Teams running SelectPdf face the same accumulating risks that accompany any discontinued library: no security patches, no runtime compatibility updates, and no CSS rendering improvements as the gap between SelectPdf's engine and modern browser capabilities widens. SelectPdf uses its own rendering engine rather than Chromium or WebKit, which means CSS support is limited to what SelectPdf implemented — modern CSS features including Flexbox, Grid, CSS variables, and certain web font loading patterns may not render correctly or at all.

This guide covers the migration from SelectPdf to IronPDF for .NET engineers evaluating or executing the switch. The migration effort is classified as Medium — SelectPdf's API surface is broad, its configuration model is detailed, and the rendering engine change requires a rendering fidelity comparison pass that is more involved than migrations between two Chromium-based libraries.

What SelectPdf Is Designed to Do

SelectPdf is a .NET HTML-to-PDF conversion library that accepts HTML content via string, file path, or URL, and converts it to PDF using its own rendering engine. The library provides a HtmlToPdf converter class with a detailed HtmlToPdfOptions configuration object covering page size, orientation, margins, headers, footers, JavaScript execution wait time, HTML element selection for conversion, and web page authentication. Post-render operations include digital signature support, password encryption, permissions, watermarking, merge and split, and AcroForm filling.

SelectPdf distributes as a NuGet package. The install footprint includes managed NuGet packages; the Community Edition and commercial edition differ in page limits and advanced features. The exact .NET support range and last release date should be verified — as SelectPdf is discontinued, active documentation may be unavailable. The primary use cases were invoice and report generation, URL-to-PDF archiving, and document export in ASP.NET applications.

Architectural Differences

SelectPdf and IronPDF both convert HTML to PDF and both provide post-render manipulation. The central architectural difference is the rendering engine. SelectPdf uses its own rendering engine, which has not tracked modern CSS standards during its discontinued period. IronPDF uses embedded Chromium — the same engine as Chrome and Edge — providing full CSS3 support including Flexbox, Grid, CSS variables, modern web fonts, and JavaScript execution.

IronPDF's ChromePdfRenderer generates PDFs from HTML strings, files, and URLs. PdfDocument handles manipulation, security, signatures, and compliance. Both implement IDisposable. The HTML string to PDF guide covers rendering configuration. For SelectPdf's HtmlToPdfOptions — covering page size, margins, orientation, wait time, and authentication — all equivalent settings are available in IronPDF's RenderingOptions. License initialization is a one-time startup call; see the license setup guide.

The install footprint difference is notable: SelectPdf's multi-package + native binary setup is replaced by IronPDF's managed NuGet package on Windows (no native binaries). On Linux, IronPDF requires Chromium system library packages — a different dependency profile from SelectPdf's, but comparable in operational overhead.

Operation Comparisons

HTML String to PDF

SelectPdf — HTML String to PDF

using SelectPdf;

// SelectPdf HtmlToPdf converter — instantiated per conversion or reused
var converter = new HtmlToPdf();

// Configure via Options object
converter.Options.PdfPageSize = PdfPageSize.A4;
converter.Options.PdfPageOrientation = PdfPageOrientation.Portrait;
converter.Options.MarginTop = 10;      // mm
converter.Options.MarginBottom = 10;
converter.Options.MarginLeft = 10;
converter.Options.MarginRight = 10;
converter.Options.JavaScriptEnabled = true;
converter.Options.JavaScriptDelay = 500;  // ms — wait for JS to complete

string html = @"
<!DOCTYPE html>
<html>
<body>
  <h1>Invoice #1042</h1>
  <p>Customer: Acme Corp</p>
  <p>Total: $1,599.00</p>
</body>
</html>";

// ConvertHtmlString returns SelectPdfDocument
using var selectDoc = converter.ConvertHtmlString(html);
// Save to file
selectDoc.Save("invoice.pdf");
// Or to byte array for HTTP response
byte[] pdfBytes = selectDoc.Save();

Concrete constraints:

  • HtmlToPdf can be reused, but verify thread safety in the SelectPdf version in use.
  • SelectPdfDocument is IDisposable — the using pattern is already required.
  • ConvertHtmlString() is synchronous. Async rendering is not available in SelectPdf.
  • SelectPdf's rendering engine has limited CSS3 support — Flexbox, Grid, and CSS variables may not render correctly. Templates requiring a rendering fidelity comparison after migration.
  • JavaScriptDelay specifies a fixed wait time in milliseconds — less reliable than event-based waiting.

IronPDF — HTML String to PDF

using IronPdf;

// ChromePdfRenderer is reusable — register as singleton in DI
var renderer = new ChromePdfRenderer();
renderer.RenderingOptions.PaperSize = IronPdf.Rendering.PdfPaperSize.A4;
renderer.RenderingOptions.PaperOrientation = IronPdf.Rendering.PdfPaperOrientation.Portrait;
renderer.RenderingOptions.MarginTop = 10;     // mm — same unit as SelectPdf
renderer.RenderingOptions.MarginBottom = 10;
renderer.RenderingOptions.MarginLeft = 10;
renderer.RenderingOptions.MarginRight = 10;
// Event-based JS wait replaces SelectPdf's fixed JavaScriptDelay
renderer.RenderingOptions.WaitFor.RenderDelay(500);

string html = @"
<!DOCTYPE html>
<html>
<body>
  <h1>Invoice #1042</h1>
  <p>Customer: Acme Corp</p>
  <p>Total: $1,599.00</p>
</body>
</html>";

// PdfDocument is IDisposable — always wrap in a using block
using var pdf = renderer.RenderHtmlAsPdf(html);
byte[] pdfBytes = pdf.BinaryData;     // equivalent to selectDoc.Save() → byte[]
pdf.SaveAs("invoice.pdf");            // equivalent to selectDoc.Save(path)

SelectPdf's converter.ConvertHtmlString(html) maps directly to renderer.RenderHtmlAsPdf(html). Margin units (mm) are consistent. The JavaScriptDelay fixed-wait is replaced by WaitFor.RenderDelay() — or more reliably by WaitFor.HtmlElement(".loaded") if the HTML exposes a loaded indicator. Full rendering configuration is in the HTML string to PDF guide.

URL to PDF with Authentication

SelectPdf — URL to PDF

using SelectPdf;

var converter = new HtmlToPdf();
converter.Options.PdfPageSize = PdfPageSize.A4;
converter.Options.JavaScriptEnabled = true;
converter.Options.JavaScriptDelay = 1000;

// SelectPdf URL authentication options
// converter.Options.HttpCookies.Add("session_id", "token-value");
// converter.Options.HttpUserName = "user";
// converter.Options.HttpPassword = "pass";

// ConvertUrl fetches the URL using SelectPdf's own HTTP client
using var selectDoc = converter.ConvertUrl("https://reports.example.com/q3");
selectDoc.Save("q3-report.pdf");

Concrete constraints:

  • SelectPdf fetches URLs using its own HTTP stack. Session cookies may need explicit forwarding.
  • The URL must be reachable from the server running SelectPdf.
  • Verify exact cookie and auth property names in SelectPdf documentation.

IronPDF — URL to PDF

using IronPdf;

var renderer = new ChromePdfRenderer();
renderer.RenderingOptions.PaperSize = IronPdf.Rendering.PdfPaperSize.A4;

// Cookie injection replaces SelectPdf's HttpCookies collection
renderer.RenderingOptions.CustomCookies =
    new System.Collections.Generic.Dictionary<string, string>
    {
        { "session_id", "your-session-token" }
    };

// WaitFor replaces JavaScriptDelay
renderer.RenderingOptions.WaitFor.HtmlElement(".report-loaded");

using var pdf = renderer.RenderUrlAsPdf("https://reports.example.com/q3");
pdf.SaveAs("q3-report.pdf");

IronPDF's in-process Chromium renders URLs from the application's own network — internal service URLs not publicly accessible can be rendered directly. The URL to PDF guide covers all authentication and wait condition options.

Headers and Footers

SelectPdf — Headers and Footers

using SelectPdf;

var converter = new HtmlToPdf();
converter.Options.PdfPageSize = PdfPageSize.A4;
converter.Options.MarginTop = 20;
converter.Options.MarginBottom = 15;

// SelectPdf HTML header/footer objects
var header = new HtmlToPdfHtmlSection(400, 40); // width, height
header.HtmlToPdfPage = new HtmlToPdfPage
{
    // SelectPdf page number tokens: {page_number} and {total_pages}
    // Verify exact token names in SelectPdf documentation — they differ from IronPDF
    HtmlString = "<div style='text-align:right;font-size:9px;'>Page {page_number}</div>"
};
converter.Header = header;
converter.Header.DisplayOnFirstPage = true;

var footer = new HtmlToPdfHtmlSection(400, 30);
footer.HtmlToPdfPage = new HtmlToPdfPage
{
    HtmlString = "<div style='text-align:center;font-size:8px;'>" +
                 "Page {page_number} of {total_pages}</div>"
};
converter.Footer = footer;

using var selectDoc = converter.ConvertHtmlString("<html><body><p>Content</p></body></html>");
selectDoc.Save("with-headers.pdf");

Concrete constraints:

  • SelectPdf uses {page_number} and {total_pages} tokens. These differ from IronPDF's {page} and {total-pages}.
  • SelectPdf's HtmlToPdfHtmlSection constructor takes width and height in pixels or points

IronPDF — Headers and Footers

using IronPdf;
using IronPdf.Editing;

var renderer = new ChromePdfRenderer();
renderer.RenderingOptions.PaperSize = IronPdf.Rendering.PdfPaperSize.A4;
renderer.RenderingOptions.MarginTop = 20;
renderer.RenderingOptions.MarginBottom = 15;

// IronPDF tokens: {page} and {total-pages}
// Note: SelectPdf uses {page_number} and {total_pages} — update all templates
renderer.RenderingOptions.HtmlHeader = new HtmlHeaderFooter
{
    Height = 12,   // mm
    HtmlFragment = "<div style='text-align:right; font-size:9px; " +
                   "font-family:Arial; padding:0 12px;'>Document Header</div>",
    DrawDividerLine = true
};

renderer.RenderingOptions.HtmlFooter = new HtmlHeaderFooter
{
    Height = 10,
    HtmlFragment = "<div style='text-align:center; font-size:8px; " +
                   "font-family:Arial;'>Page {page} of {total-pages}</div>"
};

using var pdf = renderer.RenderHtmlAsPdf("<html><body><p>Document content.</p></body></html>");
pdf.SaveAs("with-headers.pdf");

The page number token syntax change — SelectPdf's {page_number} / {total_pages} to IronPDF's {page} / {total-pages} — must be applied to every header and footer HTML template. Old tokens render as literal text without error. The headers and footers guide covers all configuration options.

Security, Signatures, and Post-Render Operations

SelectPdf — Security and Signatures

using SelectPdf;

var converter = new HtmlToPdf();
using var selectDoc = converter.ConvertHtmlString("<html><body>Content</body></html>");

// SelectPdf password and permissions
selectDoc.Security.OwnerPassword = "ownerpass";
selectDoc.Security.UserPassword  = "userpass";
selectDoc.Security.CanPrint = true;
selectDoc.Security.CanCopyContent = false;

// SelectPdf digital signature
// selectDoc.Sign("cert.pfx", "pfx-password"); // verify method signature

selectDoc.Save("secured.pdf");

Concrete constraints:

  • Verify SelectPdf's digital signature API in available documentation — it may vary by version and edition.
  • SelectPdf's permission model uses Can* boolean properties. IronPDF uses typed security settings on PdfDocument.SecuritySettings.

IronPDF — Security and Signatures

using IronPdf;
using IronPdf.Signing;

var renderer = new ChromePdfRenderer();
using var pdf = renderer.RenderHtmlAsPdf("<html><body><p>Secured document.</p></body></html>");

// Password and permissions
pdf.SecuritySettings.OwnerPassword = "ownerpass";
pdf.SecuritySettings.UserPassword  = "userpass";
pdf.SecuritySettings.AllowUserPrinting =
    IronPdf.Security.PdfPrintSecurity.FullPrintAllowed;
pdf.SecuritySettings.AllowUserCopyPasteContent = false;

// Digital signature
var sig = new PdfSignature("cert.pfx", "pfx-password")
{
    SigningReason  = "Approved for distribution",
    SigningLocation = "Chicago, IL"
};
pdf.Sign(sig);

pdf.SaveAs("secured-and-signed.pdf");

SelectPdf's selectDoc.Security. properties map directly to pdf.SecuritySettings.. The digital signature API replaces SelectPdf's signing call with PdfSignature + pdf.Sign(). The passwords and permissions guide and digital signatures guide cover all available security options.

Breaking Changes & Gotchas

  • Discontinued status — primary migration driver: SelectPdf receives no security patches, no runtime compatibility updates, and no CSS rendering improvements. Staying on a discontinued library accumulates operational risk that compounds over time.
  • Rendering engine change requires fidelity comparison: SelectPdf uses its own rendering engine. IronPDF uses Chromium. Render every document type and compare output — the engine change is the primary source of unexpected differences. CSS that worked in SelectPdf's engine may render differently in Chromium (usually an improvement, occasionally a layout adjustment is needed).
  • Page number token syntax: SelectPdf uses {page_number} and {total_pages}. IronPDF uses {page} and {total-pages}. Update all header/footer HTML templates. Old tokens render as literal text without error.
  • SelectPdfDocument → PdfDocument disposal: SelectPdf's SelectPdfDocument is IDisposable. IronPDF's PdfDocument is also IDisposable. The pattern is the same
  • ConvertHtmlString() is synchronous: SelectPdf's conversion is synchronous. IronPDF offers RenderHtmlAsPdfAsync() — replace any Task.Run() wrappers with the async method.
  • HtmlToPdfHtmlSection model replaced: SelectPdf's header/footer objects require separate class instantiation. IronPDF's HtmlHeaderFooter is simpler — inline string fragments, height in mm.
  • Namespace change: Remove using SelectPdf;. Replace with using IronPdf;.
  • License key required: SelectPdf has its own licensing model. IronPDF requires IronPdf.License.LicenseKey at startup.
  • Multi-package + native binary removal: Remove SelectPdf's native binary packages from deployment artifacts and Docker images. On Linux, add Chromium system library packages.
  • StartHtmlElement / EndHtmlElement: SelectPdf's Options.StartHtmlElementId and EndHtmlElementId allow converting only a portion of an HTML page. IronPDF does not have a direct equivalent — restructure the HTML or use JavaScript to hide unwanted content before rendering.

Migration Checklist

  1. Audit all SelectPdf call sites: List every HtmlToPdf instantiation, Options.* configuration, ConvertHtmlString(), ConvertUrl(), ConvertHtmlFile(), header/footer setup, security settings, and signature calls.
  2. Identify header/footer token syntax: Find every {page_number} and {total_pages} occurrence in header/footer HTML. Plan replacement with {page} and {total-pages}.
  3. Flag StartHtmlElement / EndHtmlElement usage: If HTML element selection is in use, plan how to restructure the HTML or apply JavaScript visibility control as a replacement approach.
  4. Install IronPDF via NuGet: dotnet add package IronPdf.
  5. Configure the license key at startup: Set IronPdf.License.LicenseKey = "YOUR-KEY"; in Program.cs. See the license setup guide.
  6. Update namespaces: Remove using SelectPdf;. Add using IronPdf; and using IronPdf.Signing; where needed.
  7. Register ChromePdfRenderer in DI: Add builder.Services.AddSingleton<ChromePdfRenderer>() with RenderingOptions configured once.
  8. Replace conversion calls: Map converter.ConvertHtmlString(html) to renderer.RenderHtmlAsPdf(html). Wrap PdfDocument in using. Access bytes via pdf.BinaryData.
  9. Replace header/footer configuration: Swap HtmlToPdfHtmlSection setup for HtmlHeaderFooter.HtmlFragment. Update all page number tokens.
  10. Replace security settings: Map selectDoc.Security. to pdf.SecuritySettings.. Map selectDoc.Sign() to new PdfSignature() + pdf.Sign().
  11. Rendering fidelity comparison: Render every document type with IronPDF against the SelectPdf output. Adjust CSS as needed — Chromium's improvements in Flexbox and Grid support may simplify templates that previously required layout workarounds.
  12. Remove SelectPdf NuGet packages: Once all replacements compile and rendering tests pass, remove SelectPdf packages and native binary artifacts.

Conclusion

When staying on SelectPdf is technically reasonable

SelectPdf's discontinued status makes continued use difficult to justify for any application with active development or maintenance. The only scenario where it is defensible is a fully frozen application — no new features, no dependency upgrades, no .NET runtime migration — where the rendering output is acceptable and the cost of migration exceeds the risk of running on a discontinued library. In practice, most active applications encounter at least one of these pressures within a short planning horizon.

Signals that indicate migration is worth the engineering effort

The discontinued status alone is typically sufficient. Additional concrete triggers: CSS rendering limitations in SelectPdf are blocking modern template designs; Flexbox or Grid layouts produce incorrect output; JavaScript-dependent content renders unreliably; security scanner alerts flag the discontinued dependency; the team is planning a .NET runtime upgrade and wants to reduce the number of in-flight changes; or a .NET version update reveals a SelectPdf compatibility gap.

What the cutover typically involves at the code level

The API remapping is systematic: HtmlToPdf → ChromePdfRenderer, ConvertHtmlString() → RenderHtmlAsPdf(), selectDoc.Security. → pdf.SecuritySettings., signing API updated. The rendering fidelity comparison pass is the most time-proportional step — it is proportional to the number of distinct HTML templates in use. Teams often find that Chromium's more complete CSS support allows simplifying templates that previously required workarounds for SelectPdf's rendering limitations.

As you look at your SelectPdf templates, are there CSS layouts that were simplified specifically to work within SelectPdf's rendering limitations — and how much template design latitude would be recovered by moving to a Chromium-based engine?
